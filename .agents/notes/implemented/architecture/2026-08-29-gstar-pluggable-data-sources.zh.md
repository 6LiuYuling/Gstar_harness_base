# Agent Note: GSTAR 可插拔数据源注册表

Status: implemented

[English](2026-08-29-gstar-pluggable-data-sources.md) | 中文

## Problem

不同 GSTAR 局点需要不同公开数据组合。由空间 Provider 持有的来源目录可以描述来源，但无法在不把几何存储与每个连接器耦合的前提下表达动态插件生命周期、逐局点准入和来源专用执行。浏览器直接调用空间采集还会绕过局点数据源开关。

公开来源的权威性和执行形态不同。OpenStreetMap 提供几何，政府官方平台是高可信核验参考，AkShare 从上游发布方展示结构化上市公司数据。把它们视为同一种采集方法，要么会声称并不存在的自动导入，要么会丢失企业数据所需的溯源和地理校验。

## Decision

`ctx.gstarDataSources` 是唯一实时注册表和局点配置能力。每个来源都是普通 Cordis 插件贡献，包含稳定 id、发布方元数据、覆盖的 AOI 类型、能力、访问方式、默认启用状态和可选同步操作。存储 Provider 只投影已加载贡献，并把它们与按局点 `WorkspaceId` 保存的持久化布尔覆盖组合起来。

直接来源携带同步操作；参考来源永远不携带。管理器会在调用连接器前拒绝未加载、已停用和只读参考来源。插件 effect dispose 会移除精确实时贡献；如果同一来源 id 再次加载，已保存覆盖仍可使用。局点删除通过现有 deletion-preparation 与 rollback 合约移除覆盖记录。

浏览器挂载生成的 `gstarDataSources` Remote，并为所选局点加载来源状态。其管理器编辑逐局点开关，只对已启用可执行来源提供同步。OpenStreetMap AOI 刷新仍是供 OSM 插件复用的 Host 空间操作，但不会出现在空间浏览器 Remote 中；浏览器采集因此必须经过来源策略边界。

GSTAR Profile 加载默认启用的 OpenStreetMap 直接 AOI／实体插件、默认关闭的 AkShare 直接实体插件，并把每个官方平台作为独立配置的参考插件行。更高层 Profile 可以移除、增加或替换这些行，而无需修改注册表或 UI。

AkShare 增强现有企业或金融 AOI，不创建几何。其有界 Python bridge 会先读取已配置的持久化 AkShare／巨潮资讯 CSV，无需联网即可解析企业名称、别名和局点地址。未配置该文件时，它会在交易所、东方财富、腾讯和新浪完整 A 股列表之间对响应与传输失败执行重试，再在相同重试边界内获取对应巨潮资讯公司概况。如果所有完整列表或必需的公司概况请求均不可用，同步会保留现有 AOI 发布并返回明确的未更新结果。只有全部必需 bridge 结果成功后，一次完整空间 patch 才会增加已接纳的 `listed_company` 实体和来源溯源。TLS 校验默认严格启用：部署可以提供 Requests CA bundle；与其互斥的显式不安全开关只影响隔离 bridge 子进程。连接器不会混并集团母公司与上市子公司，也不会接纳相邻行政区地址。

## Alternatives considered

**把目录和 OSM 刷新继续留在 `gstarSpatial`。** 拒绝，因为几何 Provider 会继续成为无关企业与官方来源的策略所有者，浏览器调用者也可以不检查局点选择就执行采集。

**保存一份全局启用来源列表。** 拒绝，因为局点覆盖、许可决定和所需增强不同。持久化身份已经是局点 `WorkspaceId`，覆盖记录就属于该身份。

**构建一个带来源类型开关的单体连接器。** 拒绝，因为增加或卸载来源需要修改中央连接器并重新部署所有来源依赖。独立 Cordis 行提供 Harness 已有的动态生命周期。

**把所有官方平台都视为直接来源。** 拒绝，因为公开链接和较高机构公信力不能证明存在自动化且许可明确的连接器。参考模式表达核验价值，但不声称已经导入。

**使用 AkShare 发现并放置所有上市公司。** 拒绝，因为公司概况不能提供可信 AOI 几何，纯名称放置还会跨越行政边界。AkShare 只在局点地址校验后增强已经空间采集的 AOI。

## Verification

Service 与 Loader 组合测试覆盖 Remote 委托、实时来源注册、默认和覆盖启用状态、局点拒绝、已停用和只读参考执行、OSM 委托、删除回滚与 dispose。来源测试覆盖参考 URL 校验、OSM 摘要、持久化档案库输入、AkShare 四来源回退、明确未更新结果、请求重试边界、严格与自定义 CA 的 TLS 配置、显式不安全隔离、简洁传输与证书诊断、输出校验、发布原子性、实体溯源，以及局点或空间投影缺失。Client 测试覆盖三个 Remote 挂载、逐局点过期加载保护、开关与同步错误、OSM 策略路由和来源管理控件。

## Consequences

GSTAR 获得来源级扩展能力和逐局点控制，无需为每个连接器扩展空间合约。新增来源要付出独立包、描述符、同步边界、测试与部署配置的成本，而不是在中央开关中增加分支。

参考来源启用目前只记录策略意图，不会抓取平台。跨来源协调和带版本流水线事务仍在注册表之外。直接插件持有自身外部限流和发布原子性，因此管理器可以强制准入，但不能把多个来源提交变成同一事务。

AkShare 需要单独管理 Python 环境，并继承上游可用性和字段时效。其输出保留来源溯源与地理过滤，但企业字段用于决策前仍需部署评审与抽样核验。
